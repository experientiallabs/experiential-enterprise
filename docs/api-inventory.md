# Gateway management API inventory — models catalog and waterfalls

Launch surface. Machine-readable source of truth for the docs workstream;
regenerated by hand in the same commits that change these routes
(`explabs/api/routes/models_catalog.py`). Scope: the product-core models
management routes ONLY. Usage reads (`/api/usage*`), credits reads
(`/api/credits`), and BYOK provider-connection writes are owned by the
integration, billing, and keys workstreams respectively and are documented by
their inventories.

Host: `control.experientiallabs.ai` (control/all API role). Every `/api/*`
call carries a bearer credential: trusted services (the web app) present the
deployment key plus, where noted, the `X-Explabs-Actor-Id` header naming the
end user; agents present an org `xpl_` API key, which implies the acting
organization. `xpl_` keys additionally require the `_CUSTOMER_KEY_ROUTES`
allowlist entries (integration workstream) before the middleware admits them
to these paths.

Errors are `{"error": message}` with optional `code`/`action`; every message
states what failed, why, and the exact next call.

```yaml
surface: gateway-models-management
host: control.experientiallabs.ai
owner: product-core
status: launch
routes:
  - method: GET
    path: /api/models
    auth: public # deployment key or (once allowlisted) xpl_ key; no actor needed
    purpose: Catalog list. Public rows for everyone; an identified caller
      (actor header or xpl_ key) additionally sees its orgs' own models.
      The web storefront serves the org-agnostic public list (no actor) from a
      shared cross-user cache and overlays each signed-in viewer's own rows
      with a thin owner=org read (see the serving note below).
    query_params:
      modality: "input modality filter: text|image|audio|video|pdf"
      category: "exact category filter (e.g. coding, owned)"
      provider: "reachable-via filter: openai|anthropic|gemini|azure_openai|openrouter|bedrock|local|fireworks|modal|experiential_cloud"
      min_context: "integer, tokens; keeps models with context_window >= value"
      max_input_micro_usd_per_million: "integer; keeps models whose cheapest input price <= value"
      supports: "supported_params key that must be true (e.g. tools, reasoning)"
      owner: "org = only the viewer's orgs' own rows (drops public); empty for anonymous callers. Powers the storefront's per-user overlay on the shared public cache."
      sort: "preferred (default) | price | age | context | throughput"
      order: "asc | desc (defaults per sort: price asc, others desc, preferred asc)"
      limit: "1..1000, default 500"
      offset: ">= 0"
    returns: "{models: [{model, providers: [...]}], total, limit, offset}.
      Each model's providers list pins experiential_cloud first when present;
      remaining lanes keep their incoming order. Display order only."
  - method: GET
    path: /api/models/{slug}
    auth: public
    purpose: Model detail: the row, its visible deployments, and the default
      waterfall chain. An org's custom model shadows a public slug for that
      org's viewers (matching gateway alias shadowing).
    query_params:
      org_id: "optional namespace pin when the slug is ambiguous across orgs"
    returns: "{model, providers: [...], default_waterfall: [rung...]}.
      providers pins experiential_cloud first when present (display order);
      default_waterfall stays the persisted chain."
    errors:
      404: unknown slug (message lists GET /api/models and POST /api/models)
      409: slug ambiguous across the viewer's orgs; pass org_id
  - method: GET
    path: /api/models/{slug}/providers
    auth: public
    purpose: The model's deployments visible to the viewer (public rows plus
      the viewer orgs' private variants). Rung ids for waterfall PUTs.
      Display order pins experiential_cloud first when present; it is not
      the waterfall.
    query_params:
      org_id: "optional namespace pin"
    returns: "{model_id, slug, providers: [...]}"
  - method: POST
    path: /api/models
    auth: org # xpl_ key (org implied) or session actor (org_id required)
    purpose: Create a custom model: one models row (org-owned), at least one
      deployment, and its default waterfall chain. Platform admins may pass
      org_id null to create public catalog rows (data-fill fan-out). Rows are
      always created unranked: the recommended set (preferred_rank) is managed
      whole-set via PUT /api/admin/recommended-models (docs/admin-api.md).
    body:
      org_id: "uuid | null (null = public row, platform admins only)"
      slug: "^[a-z][a-z0-9._-]{0,127}$ (letter-first; becomes the gateway alias)"
      display_name: "1..200 chars"
      description: "optional, <= 2000 chars"
      release_date: "optional ISO date"
      context_window: "optional int >= 1"
      max_output_tokens: "optional int >= 1"
      input_modalities: "subset of text|image|audio|video|pdf, default [text]"
      output_modalities: "same vocabulary, default [text]"
      supported_params: "boolean map (tools, temperature, reasoning, ...)"
      category: "optional, <= 64 chars"
      tags: "string list"
      providers: "non-empty list of deployment objects (see POST providers body)"
    returns: "201 {model, providers, default_waterfall}; 200 on exact replay"
    errors:
      404: org not found / not a member
      409: slug exists in the namespace with different attributes
      422: validation (org_id missing for session actors, vocabulary, base_url rules)
    idempotency: exact replay converges on the existing rows (200); conflicts 409
  - method: POST
    path: /api/models/{slug}/providers
    auth: org
    purpose: Add a deployment to an existing model, including a local variant
      (provider local + base_url) on a public model, which becomes the org's
      private route to it. billing_source is always customer_managed; the
      platform-funded lane is seeded by operations, never self-asserted.
    body:
      org_id: "uuid | null (null = public deployment, platform admins only)"
      provider: "openai|anthropic|gemini|azure_openai|openrouter|bedrock|local|fireworks|modal|experiential_cloud"
      provider_model_id: "the wire id at that provider, 1..256 chars"
      base_url: "required for local and modal, optional for experiential_cloud
        (worker env supplies a shared origin when omitted), forbidden otherwise;
        org-owned experiential_cloud rows are rejected; strict
        http(s) endpoint grammar (host, optional port, optional path; no
        userinfo/query/fragment)"
      region: "optional (bedrock)"
      api_version: "optional (azure_openai)"
      provider_connection_id: "optional BYOK pin; must be the owning org's
        connection with a matching provider"
      input_micro_usd_per_million: "optional int >= 0 (null = unknown, never 0)"
      cached_input_micro_usd_per_million: "optional int >= 0"
      output_micro_usd_per_million: "optional int >= 0"
      reasoning_micro_usd_per_million: "optional int >= 0"
      pricing_source: "optional label; pricing_effective_at stamps automatically"
      capabilities: "boolean map mirrored into gateway deployment capabilities"
      uptime_30d: "optional 0..100"
      throughput_tps: "optional >= 0"
      latency_p50_ms: "optional >= 0"
      stats_source: "openrouter | observed"
    returns: "201 deployment view; 200 on exact replay"
    errors:
      404: model not visible / foreign org / unknown pinned connection
      409: route identity exists with different attributes
      422: base_url rules, pin mismatch, vocabulary
    idempotency: identity key is (model, provider, provider_model_id, org, base_url)
  - method: GET
    path: /api/models/{slug}/waterfall
    auth: org
    purpose: Read the model's default chain plus the acting org's override.
    query_params:
      org_id: "required for session actors; xpl_ keys imply theirs; platform
        admins may omit it to read the default chain only"
    returns: "{model_id, slug, org_id, default: [rung...], override: [rung...] | null}"
  - method: PUT
    path: /api/models/{slug}/waterfall
    auth: org
    purpose: Replace the acting org's waterfall override with an ordered
      deployment id list (position 0 = primary; the order IS the spill
      order). An empty list clears the override. Platform admins with
      org_id null replace the model's DEFAULT chain (public rungs only).
    body:
      org_id: "uuid | null (null = default chain, platform admins only)"
      model_provider_ids: "ordered deployment ids from GET .../providers; [] clears"
    returns: "200 with the same shape as GET"
    errors:
      404: model or deployment id not visible (foreign rows are
        indistinguishable from absent ids)
      422: duplicate ids, org_id missing for session actors
    idempotency: naturally idempotent (replace semantics)
notes:
  - Writes never trigger catalog snapshot rebuilds directly; the gateway's
    catalog builder polls the tables every 15 seconds on row timestamps
    (inserts and set_updated_at triggers cover it; a pure-delete waterfall
    clear touches the parent models row). A worker that misses a
    DB-authoritative alias revision catches up on a route-resolution miss,
    subject to a short throttle, instead of returning 503 until its next poll.
  - Custom models and private deployments are visible and callable only for
    their org; GET /v1/models on api.experientiallabs.ai reflects the same
    scoping (integration workstream).
  - Tenancy is trigger-enforced in the schema; route pre-checks translate
    those rejections into the 4xx messages above instead of 500s.
  - Storefront serving (apps/web/lib/models-catalog/server.ts): the /models
    page reads the org-agnostic public list (no actor) from ONE shared
    cross-user cache (Next Data Cache via unstable_cache, tag `models-catalog`,
    revalidate 120s), so every visitor is served the last-good catalog with no
    per-visit refetch or skeleton and a background refresh (stale-while-
    revalidate) picks up new/removed public models within ~120s. A create
    (POST /api/models) busts the tag for immediate propagation. Org-scoped rows
    never enter the shared cache; a signed-in viewer's own models overlay the
    shared base via a thin per-user owner=org read.
```

# Gateway control endpoints — usage, key limits, workers, catalog

Owner: platform-integration workstream (`explabs/api/routes/gateway_admin.py`).
Same host and credential contract as above; the routes marked "customer keys"
are on the `_CUSTOMER_KEY_ROUTES` allowlist, and the key acts as its org at
user strength. Detailed parameter semantics live in the route module's
docstrings.

| Route | Auth | Purpose |
|---|---|---|
| `GET /api/whoami` | customer keys; session actors | Identity bootstrap: `{org_id, org_slug, org_name}` for the org the credential acts for. An `xpl_` key resolves to its org; a session actor to their sole membership (409 when several orgs or platform admin — no single answer; 401 on a bad/absent key). |
| `GET /api/gateway/usage/daily?org_id=&scope=self\|org&user_id=&from=&to=&group_by=day\|model\|member&limit=` | org member; customer keys (`scope=org`) | Grouped `gateway_usage_daily` rollup. `scope=self&group_by=day` is the account Overview series (per-user per-day spend/tokens/requests, all-time capable); `group_by=model` is the top-models list; `group_by=member` the org breakdown. |
| `GET /api/gateway/usage/events?org_id=&api_key_id=&from=&to=&cursor=&limit=` | org member; customer keys | Keyset-paginated `gateway_usage_events` stream, newest first. Exposes both `cost_micro_usd` (charged) and `estimated_cost_micro_usd` (attributed, never charged). Pass `next_cursor` back as `cursor`. |
| `GET /api/gateway/keys/{api_key_id}/limits` | org member; customer keys | Effective per-key guardrails, defaults included (`source: explicit\|default`). |
| `PUT /api/gateway/keys/{api_key_id}/limits` | org admin | Set per-key guardrails `{daily_spend_cap_micro_usd, requests_per_minute, tokens_per_minute}`; full-resource semantics, null/omitted = uncapped. |
| `GET /api/gateway/workers` | platform admin | Worker registry with derived staleness (heartbeat older than 60s). |
| `GET /api/gateway/catalog?org_id=` | org member; customer keys | Resolved alias list as the org sees it: public + own custom models with org-shadows-public applied, current revision id, and per-provider lane (`pass_through`/`platform_funded`). |

Customer-key allowlist entries carried by the integration workstream for
other workstreams' routes: `GET /api/keys`,
`GET /api/orgs/{org_id}/provider-connections`,
`PUT /api/orgs/{org_id}/provider-connections/{provider}`, and
`POST /api/orgs/{org_id}/provider-connections/{provider}/check|spend-refresh`
(keys workstream — agents can connect/verify the org's BYOK provider keys),
and `GET|POST /api/models`, `GET /api/models/{slug}`,
`GET|POST /api/models/{slug}/providers`,
`GET|PUT /api/models/{slug}/waterfall` (product-core, section above).
